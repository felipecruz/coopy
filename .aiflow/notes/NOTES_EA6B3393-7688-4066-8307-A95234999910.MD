# Using the new API

- Use `coopy.open(Domain, path)` or `coopy.open(Domain(), path)`; existing initialization imports remain valid.
- Use `coopy.control(system)` for snapshots, closure, timers, and replication. Domain methods named `close`, `shutdown`, or `take_snapshot` now take precedence.
- Direct `with coopy.open(...)` works. For static typing, use `with coopy.control(coopy.open(...)) as domain:`.
- Switch to `start_primary` and `start_replica`. Deprecated master/slave aliases emit warnings and are scheduled for removal in v0.9.
- Initialization no longer creates `coopy.log`. Call `coopy.logging_config(existing_directory)` if you want the rotating file handler.

# Serialization and migration

Pickle remains the compatible default. Back up storage before migrations and keep pickle input trusted: HMAC integrity does not make arbitrary pickle safe.

For JSON, register every domain type with explicit encode/decode functions and pass `serializer=coopy.JsonSerializer(registry)` on every open. JSON currently requires tree-shaped state; it rejects cycles and shared container/object identities. Registered decoders and replayed domain methods remain trusted application code.

Use `ActionSchemas` for consecutive per-method journal upgrades and `PickleSerializer(class_aliases=...)` for moved classes. Retain migrations while old files remain recovery inputs. No automatic format conversion or snapshot-state migration is provided. Replication still uses trusted-peer pickle and compatible peer code is required.

See `docs/modern-api.rst` for executable API patterns, serializer contracts, recovery behavior, and migration examples.

# Enable integrity protection

- Generate a high-entropy key once, such as `secrets.token_bytes(32)`, and keep it outside the data directory. Back it up separately and securely.
- Open a new directory with `init_persistent_system(Domain, "signed-data", secret=key)` and supply the same nonempty bytes on every restart, including salvage inspection.
- Back up the complete data directory, including `.coopy-integrity`. Keep numbered filenames intact. The key is never written by coopy.
- Existing unsigned data still opens without a secret. To migrate, recover trusted data and export domain state into a separate new signed directory. There is no automatic migration or key rotation.

# Handle verification failures

Strict recovery raises `coopy.restore.RecoveryError`; inspect `error.report.stop` for the file, offset, record, and verification detail. Salvage with the same secret returns a report and `system=None` on authentication failure. Neither path unpickles any recovery input when verification fails. Preserve failed storage and investigate the key, backup, and file integrity; do not bypass verification by removing the secret.

# Limits and validation

HMAC detects tampering but does not encrypt data. It cannot detect every valid rollback, whole-file deletion, or removal of complete trailing records. Protect storage access and keep backups. Replication still requires trusted peers.

Recovery retains the selected snapshot and journals in memory before unpickling; take regular checkpoints to limit memory use. Signed records preserve aliases within each record but do not preserve cross-record object identity. Use stable domain IDs.

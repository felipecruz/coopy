# F18 setup and operating notes

Implementation commit: `1b2d9f06309c5e31d25b86139a0c59f1ec1f23e8`.

## Enable batching only for workloads that benefit

Open with `durability="sync", group_commit_delay=0.001` to batch concurrent calls. The default delay is zero and retains immediate per-call sync. Each call waits for its batch to synchronize; failed batches raise and disable later mutations. There is no rollback. A positive delay adds latency to isolated calls, so compare both settings on your storage before enabling it.

## Install snapshot compression extras

Use `pip install 'coopy[zstd]'` or `pip install 'coopy[lz4]'`, then set `snapshot_compression="zstd"` or `"lz4"` when opening. Keep the matching extra installed for recovery. Compression is detected from the checkpoint; the original serializer and secret are still required. Compressed/signed snapshots use whole payloads in memory.

## Fork snapshots require application review

Use `coopy.control(proxy).take_snapshot(mode="fork", fork_safe=True)` only from a single-threaded POSIX main process outside macOS, with no unsafe native threads, inherited locks, at-fork hooks, serializer callbacks, or external/shared resources. Detectable unsupported configurations warn and use blocking snapshots. macOS and threaded applications retain blocking snapshots.

A successful fork returns a job; the parent can write immediately. Call `job.wait(timeout=60)` before another checkpoint. Wait publishes the checkpoint; close also waits and propagates failures. Timeout kills/reaps the child. Never reap the job's child yourself. Consult `docs/snapshots.rst` before opting in.

## Remaining validation

Run the Linux CI matrix and collect blocking-versus-fork pause measurements on supported Linux deployment hardware. Local fork mechanism tests passed in pristine macOS subprocesses through a test-only guard bypass; that does not certify production macOS or Linux behavior. The production macOS guard remains enabled.

Reproduce the checked-in before/after measurements with `scripts/benchmark_persistence.py` as described in `docs/performance.rst`. The results describe one shared macOS host, warm-cache recovery, and specific workloads; they are not general throughput or pause guarantees.

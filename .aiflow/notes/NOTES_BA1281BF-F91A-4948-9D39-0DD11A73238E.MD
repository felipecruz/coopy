# F13 bootstrap and catch-up

Implementation: `a25dfb129f8f97e0e8e600780c8438290769eae5`.

## Using a replica

- Upgrade master and slaves together; the framed authentication and ready marker require compatible peers.
- Wait for `connection.wait_until_synchronized(timeout)` before readonly queries. Readiness covers the snapshot and actions before the catch-up marker; later updates are asynchronous.
- After connection failure, inspect `replica.slave.error`. A failed, interrupted, or shut-down slave remains guarded as unsynchronized.
- For an explicit reconnect, call `replica.shutdown()`, then `replica.start_slave(...)` and wait again. A second active receiver and slave-to-master promotion are rejected.
- Access replicated state through readonly proxy methods. Direct `.obj` access and `@unlocked` methods bypass protection.

## Operational limits

Use trusted peers and a trusted network: passwords are unencrypted and payloads use pickle. Pending queues have no byte limit; monitor memory and disconnect persistently slow replicas. Snapshot serialization pauses master mutations. Automatic failover, automatic reconnect, and durable slave restart are outside this feature.

# Recovery and durability changes

## Choose the opening policy

Strict recovery is now the default. Catch `coopy.restore.RecoveryError` and inspect its `.report`; do not start serving requests when initialization raises.

To inspect incomplete recovery without creating a writable journal, call `init_persistent_system(Domain, basedir="data", recovery="salvage")`. This returns `RecoveryResult`, not a proxy. Inspect `.report.stop`, `.report.replayed`, and `.report.legacy_actions`. A divergent attempted method can have changed `.system`; the report flags this. Preserve the directory and reconcile state before exporting to a separate directory.

## Enable synchronous acknowledgments

Open with `init_persistent_system(Domain, basedir="data", durability="sync")` on every restart. The default remains `"buffered"`. Synchronous mode waits for `os.fsync` on complete journal records and synchronizes directory changes. Its guarantee depends on the POSIX filesystem and device; actual power loss was not tested.

Catch `coopy.journal.PersistenceError`: memory may already have changed and the record may already exist. Do not blindly retry. Further proxy mutations/checkpoints are refused after journal failure. Stop callers, close while handling possible close errors, preserve storage, and inspect recovery. No rollback is provided.

A snapshot directory-sync failure can happen after checkpoint publication; retain the previous checkpoint and all journals even if a new checkpoint is visible.
